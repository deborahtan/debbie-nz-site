The measurement pipeline

10 pieces that take a project from brief to trustworthy data, in the order they run.

  • 🗺️ ✅ Done · in use Measurement plan, event spec and data dictionary Turns a brief and a site audit into a measurement plan, an event spec and a data dictionary. PlanningGA4

    On the roadmap PlanDone

    • Writing measurement plans
    • Writing full measurement frameworks
    See it on the impact / effort matrix →

    What it does

    • Reads the brief and the site audit
    • Maps business goals to KPIs, then to the events and parameters that measure them
    • Writes the event spec and a data dictionary with consistent naming
    • Becomes the single source of truth that every later step builds from

    Why it helps

    • Days of planning becomes hours
    • The same naming rules across every project
    • Everything downstream (GTM, dev briefs, tests) traces back to one approved plan
  • 🏷️ ✅ Done · in use GTM container builder Builds the Tag Manager container (tags, triggers and variables) straight from the approved tracking plan. GTMTracking

    On the roadmap BuildDone

    • Creating GTM containers
    • Adding new tags to existing setups
    See it on the impact / effort matrix →

    What it does

    • Reads the approved tracking plan
    • Creates the tags, triggers and variables to match it exactly
    • Sets consent requirements on every tag
    • Outputs a container that imports in one step

    Why it helps

    • No more hand-building tags one by one
    • The container always matches the spec
    • Easy to rebuild when the plan changes
  • ⚙️ ✏️ Drafted GA4 + GTM config updater Pushes approved GA4 and GTM configuration changes live automatically. GA4Automation

    Next: Drafted, not in use yet.

    On the roadmap BuildTo do

    • Updating GA4 & GTM configs
    • Small tweaks to existing tag configs
    See it on the impact / effort matrix →

    What it does

    • Takes a set of approved changes (events, key events, custom definitions, settings)
    • Applies them to the GA4 property only after sign-off
    • Keeps a record of what changed and when

    Why it helps

    • No manual clicking through GA4 admin
    • Changes match exactly what was approved
    • A clear audit trail of every change
  • 🔍 ✅ Done · in use GA4 + GTM audit Checks existing Tag Manager containers and GA4 set-up, built in Apps Script and in use today. AuditGA4GTMApps Script

    On the roadmap Audit & monitorDone

    • Auditing complex tag setups
    See it on the impact / effort matrix →

    What it does

    • Reviews GTM containers: tags, triggers, variables, naming, duplicates, unused items and consent settings
    • Reviews the GA4 property: data streams, events, key events, custom definitions, retention and product links
    • Checks everything against a fixed rule set, so the result is deterministic
    • Looks at configuration only, never personal data

    Why it helps

    • Hours of clicking through admin screens becomes minutes
    • Re-run it after changes and compare like with like
    • Catches gaps before they quietly cost months of data
  • 🎫 ✅ Done · in use Developer briefs and ticketing Turns an approved tracking plan into a ready-to-brief spec for developers. Dev handoffJiraConfluence

    Next: Next: creating Jira and Confluence tickets automatically.

    On the roadmap BuildDone

    • Writing developer briefs
    • Writing site data collection specs
    See it on the impact / effort matrix →

    What it does

    • Writes a developer brief per event: the dataLayer code to add, where it fires and what each value should be
    • Adds acceptance criteria and test steps so 'done' is clear
    • Coming next: creating Jira tickets and Confluence pages automatically, linked back to the plan

    Why it helps

    • Developers get exactly what they need, first time
    • Every ticket traces back to an approved line in the plan
    • Far less back-and-forth between analysts and developers
  • 🎭 ✏️ Drafted Automated website overview, audit and testing A robot browser that runs through a site to check the dataLayer and tracking fire correctly. It also works as a standalone audit tool. QAPlaywrightAudit

    Next: Refining.

    On the roadmap TestDoing

    • Funnel QA: run a booking and check tags fire at every step
    See it on the impact / effort matrix →

    What it does

    • Opens pages and runs key journeys (page views, clicks, forms, checkout) like a real visitor
    • Watches network requests to see which tags fired and what they sent
    • Checks the dataLayer at each step against the spec
    • Reads the site's Content Security Policy and flags any vendor it would block
    • Works in Tag Manager preview before release, and on the live site to diagnose problems

    Why it helps

    • Tests changes before they go live
    • Diagnoses production issues in minutes
    • Catches silent breakages, like a release that kills a conversion tag
  • 💬 ✅ Done · in use Conversational analytics: event health Ask plain-English questions about event health and get validated answers back. Done and in use. AI agentsBigQuery

    On the roadmap Insight & agentsDone

    • Implementing conversational analytics
    See it on the impact / effort matrix →

    What it does

    • Runs on Google's Conversational Analytics API over BigQuery, with no Looker licence needed
    • Answers questions like 'which events dropped this week?' or 'is purchase missing currency?'
    • Validates its answers before showing them

    Why it helps

    • Event health without writing SQL
    • Answers you can trust, because they're checked
    • Much cheaper than an enterprise BI licence
  • 🚨 ✅ Done · in use Event-health monitoring (part of conversational analytics) A branch of the conversational analytics agent: checks event health on demand and flags issues. MonitoringGeminiBigQuery

    On the roadmap Audit & monitorDone

    • Setting up tracking health monitoring
    See it on the impact / effort matrix →

    What it does

    • Runs health checks across key events when prompted
    • Flags drops, spikes, missing parameters and broken values
    • Runs on request rather than always-on, to keep costs under control

    Why it helps

    • Problems surface before a report goes out wrong
    • Cost stays predictable
    • Pairs with the conversational analytics agent for follow-up questions
  • 🧪 ✏️ Drafted Agent evaluation + AI harness Runs the agents at scale instead of on a laptop, and scores how well they answer. AI agentsTesting

    Next: Refining.

    On the roadmap Insight & agentsDoing

    • Evaluating and testing agents
    See it on the impact / effort matrix →

    What it does

    • Runs batches of test questions against an agent
    • Scores the answers and flags made-up ones
    • Tracks the Google Cloud cost of each agent and each run

    Why it helps

    • Find weak spots before people rely on an agent
    • Scale testing without tying up anyone's machine
    • Costs are visible, not a surprise on the bill
  • 📰 ✅ Done · in use GA4 / GMP / GCP news summary Pulls the latest GA4, Google Marketing Platform and Google Cloud news into a monthly summary. ResearchAI
