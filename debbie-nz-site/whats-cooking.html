The automations I'm building to take the grunt work out of measurement, from the first tracking plan to the last health check. Tap any one to see what it does and why it helps.

The measurement pipeline

Eleven pieces that take a client from brief to trustworthy data, in the order they run.

  • 🗺️ ✏️ Drafted Measurement plan, event spec and data dictionary Turns a client brief and a site audit into a measurement plan, an event spec and a data dictionary. PlanningGA4

    Next: Refining it, and customising it to each client's needs.

    What it does

    • Reads the client brief and the site audit
    • Maps business goals to KPIs, then to the events and parameters that measure them
    • Writes the event spec and a data dictionary with consistent naming
    • Becomes the single source of truth that every later step builds from

    Why it helps

    • Days of planning becomes hours
    • The same naming rules across every client
    • Everything downstream (GTM, dev briefs, tests) traces back to one approved plan
  • 🏷️ ✏️ Drafted GTM container builder Builds the Tag Manager container (tags, triggers and variables) straight from the approved tracking plan. GTMTracking

    Next: Refining.

    What it does

    • Reads the approved tracking plan
    • Creates the tags, triggers and variables to match it exactly
    • Sets consent requirements on every tag
    • Outputs a container that imports in one step

    Why it helps

    • No more hand-building tags one by one
    • The container always matches the spec
    • Easy to rebuild when the plan changes
  • 🔍 ✅ Done · in use GA4 + GTM audit Checks existing Tag Manager containers and GA4 set-up, built in Apps Script and in use today. AuditGA4GTMApps Script

    What it does

    • Reviews GTM containers: tags, triggers, variables, naming, duplicates, unused items and consent settings
    • Reviews the GA4 property: data streams, events, key events, custom definitions, retention and product links
    • Checks everything against a fixed rule set, so the result is deterministic
    • Looks at configuration only, never personal data

    Why it helps

    • Hours of clicking through admin screens becomes minutes
    • Re-run it after changes and compare like with like
    • Catches gaps before they quietly cost months of data
  • 🎫 🚧 Blocked Developer briefs and ticketing Turns an approved tracking plan into a ready-to-brief spec for developers. Dev handoffJiraConfluence

    Next: Waiting on build time. Next up: generating the briefs, then exploring Jira and Confluence.

    What it does

    • Writes a developer brief per event: the dataLayer code to add, where it fires and what each value should be
    • Adds acceptance criteria and test steps so 'done' is clear
    • Exploring: creating Jira tickets and Confluence pages automatically, linked back to the plan

    Why it helps

    • Developers get exactly what they need, first time
    • Every ticket traces back to an approved line in the plan
    • Far less back-and-forth between analysts and developers
  • 🎭 ✏️ Drafted Automated website overview, audit and testing A robot browser that runs through a site to check the dataLayer and tracking fire correctly. It also works as a standalone audit tool. QAPlaywrightAudit

    Next: Refining.

    What it does

    • Opens pages and runs key journeys (page views, clicks, forms, checkout) like a real visitor
    • Watches network requests to see which tags fired and what they sent
    • Checks the dataLayer at each step against the spec
    • Reads the site's Content Security Policy and flags any vendor it would block
    • Works in Tag Manager preview before release, and on the live site to diagnose problems

    Why it helps

    • Tests changes before they go live
    • Diagnoses production issues in minutes
    • Catches silent breakages, like a release that kills a conversion tag
  • 💬 ✅ Done · in use Conversational analytics: event health Ask plain-English questions about event health and get validated answers back. Done and in use. AI agentsBigQuery

    What it does

    • Runs on Google's Conversational Analytics API over BigQuery, with no Looker licence needed
    • Answers questions like 'which events dropped this week?' or 'is purchase missing currency?'
    • Validates its answers before showing them

    Why it helps

    • Event health without writing SQL
    • Answers you can trust, because they're checked
    • Much cheaper than an enterprise BI licence
  • 🚨 ♊ Built for Gemini Event-health monitoring and alerts Checks event health on demand and flags issues. Built on Gemini. MonitoringGeminiBigQuery

    What it does

    • Runs health checks across key events when prompted
    • Flags drops, spikes, missing parameters and broken values
    • Runs on request rather than always-on, to keep costs under control

    Why it helps

    • Problems surface before a report goes out wrong
    • Cost stays predictable
    • Pairs with the conversational analytics agent for follow-up questions
  • 🧪 ✏️ Drafted Agent evaluation + Cloud Run AI harness Runs the agents at scale in the cloud instead of on a laptop, and scores how well they answer. AI agentsCloud RunTesting

    Next: Refining.

    What it does

    • Runs batches of test questions against an agent on Cloud Run
    • Scores the answers and flags made-up ones
    • Tracks the Google Cloud cost of each agent and each run

    Why it helps

    • Find weak spots before people rely on an agent
    • Scale testing without tying up anyone's machine
    • Costs are visible, not a surprise on the bill
  • ⚙️ 🧺 Done · not in use yet GA4 config updates on approval Pushes approved GA4 configuration changes live in a property automatically. GA4Automation

    Next: Refining before first live use.

    What it does

    • Takes a set of approved changes (events, key events, custom definitions, settings)
    • Applies them to the GA4 property only after sign-off
    • Keeps a record of what changed and when

    Why it helps

    • No manual clicking through GA4 admin
    • Changes match exactly what was approved
    • A clear audit trail of every change
  • 🕸️ 🔬 Not started · R&D Enterprise BigQuery set-up + knowledge graph Stands up the BigQuery structure and a knowledge graph in Google Cloud directly from a client's tracking definitions. BigQueryData engineeringGCP

    Next: Client-requested. Researching what can be automated.

    What it does

    • Reads the tracking definitions from the data dictionary
    • Creates the BigQuery datasets, tables and data-engineering fields to match
    • Builds a knowledge graph so business terms, events and tables are linked

    Why it helps

    • Warehouse and tracking stay in sync by design
    • Agents and analysts share the same definitions
    • Weeks of set-up shrinks once it's automated
  • 📰 ✏️ Drafted Client-specific GA4 / GMP / GCP news summary Pulls the latest GA4, Google Marketing Platform and Google Cloud news into a client-ready summary. ResearchAI

    Next: Customising per client.

    What it does

    • Searches a fixed window across Google release notes, practitioners and trusted publications
    • Keeps only what changed, with every item dated and sourced
    • Explains what it means for that client and what to do about it

    Why it helps

    • Clients hear about changes from you first
    • Staying current takes a read, not a day of searching
    • The same engine behind On the Pulse

Side experiments

Things I'm trying on my own time.

  • 🖥️ 🛠️ In progress BigQuery agents with a custom front end Turning the conversational analytics agents into a proper product, not just a chat window. AI agentsProduct

    What it does

    • A custom interface with filters, and an intent agent that works out what you're really asking
    • A semantic layer so business terms mean one thing
    • Purpose-built agents, like segmentation, health checks and explaining BigQuery billing spikes

    Why it helps

    • Self-serve answers for people who don't write SQL
    • The same patterns I teach in my BigQuery agents workshops
  • 🔗 🧪 Testing UTM naming checker Catches messy campaign tags before they split reporting into a hundred versions of 'Facebook'. AuditBigQueryCampaigns

    What it does

    • Reads naming rules from a Google Sheet marketers can update
    • Checks every UTM combination in the GA4 BigQuery export with SQL
    • Flags typos, wrong case and unknown values, with the traffic each affects
    • Answers follow-up questions through BigQuery's built-in Gemini agent

    Why it helps

    • Clean channel reporting without monthly clean-up
    • Marketers own the rules; no code edits
    • Shows the cost of bad tagging, so fixes get prioritised
  • 🤖 🧭 Exploring Data Agent Kit experiments Testing Google's new Data Agent Kit, which lets coding agents query, build pipelines and do data science on BigQuery. AI agentsBigQuery

    What it does

    • Connects a coding agent to BigQuery with Google's own skills and tools
    • Puts guardrails in first: an IAM policy blocking write actions

    Why it helps

    • Finds out what's useful versus demo-only
    • Compares Google with Snowflake, Databricks and Microsoft

    Why it helps
